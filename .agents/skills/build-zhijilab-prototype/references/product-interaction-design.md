# 交互设计原则

交互设计的价值不是增加界面表现，而是让用户能够理解当前情境、预期操作结果，并在出现偏差时继续完成操作。以下原则用于判断一个交互方案是否成立，不规定具体组件或页面形式。

## 1. 可理解性优先

- 用户应当从界面本身理解当前对象、所处状态、可执行操作及其影响，不依赖额外说明来解释基本结构。
- 使用符合业务认知的名称和关系，避免把系统实现、数据结构或内部流程直接暴露给用户。
- 操作名称应表达明确动作和对象，避免含义宽泛、结果不确定的表述。
- 当一个设计需要大量解释才能被理解时，应先简化结构，而不是继续补充说明。

## 2. 用层级引导注意力

- 信息和操作的视觉权重应与其重要性一致，不让所有内容同时争夺注意力。
- 在同一任务上下文中建立明确的主次关系，避免出现多个同等强调但方向不同的操作。
- 通过位置、分组、留白、顺序和视觉强弱表达关系，不依赖装饰制造层次。
- 复杂内容逐步展开：先呈现判断和行动所需的信息，再提供细节与低频能力。

## 3. 保持一致与可预测

- 相同含义使用相同名称、组件、位置和反馈；不同含义不复用容易混淆的表达。
- 优先遵循平台已有模式和用户已经形成的经验，降低重新学习成本。
- 操作结果应符合用户根据界面线索形成的预期，不制造意外跳转、状态变化或影响范围。
- 只有当既有模式无法解决问题时才引入新模式，并确保差异清晰且有实际价值。

## 4. 让系统状态始终可见

- 用户应随时知道系统当前处于什么状态、刚刚发生了什么、是否仍在处理以及下一步可以做什么。
- 反馈的时机、位置和强度应与操作影响匹配：即时操作即时反馈，局部变化就近反馈，重要结果持续可见。
- 加载、完成、失败、空白、禁用和只读等状态应具有不同且准确的语义，不能只做视觉变化。
- 状态变化时尽量保持界面结构稳定，减少用户重新定位和判断的成本。

## 5. 让用户保持控制

- 重要变化应由用户明确触发，不自动替用户作出有后果的决定。
- 为取消、返回、撤销或修正保留合理路径，避免把用户困在不可逆流程中。
- 不因失败、关闭、返回或切换而无故丢失用户已经投入的有效内容。
- 对不可逆或影响范围较大的操作，在执行前明确对象、结果和影响；确认不是例行步骤，而是风险控制手段。

## 6. 优先预防错误，并支持恢复

- 在用户作出选择时呈现必要约束，让不可行选项尽早暴露，而不是等提交后统一报错。
- 能通过合理默认值、输入限制、依赖关系和操作条件避免的错误，不留给错误提示解决。
- 错误反馈应指出发生位置、具体原因和修正方式，不使用无法指导行动的笼统表述。
- 错误发生后保留上下文和有效输入，使用户能够从失败处继续，而不是从头开始。

## 7. 保持过程与上下文连续

- 页面、步骤和状态之间的变化应能看出来源与去向，让用户理解自己为何来到这里以及如何返回。
- 在合理范围内保留筛选条件、选中对象、浏览位置和操作结果，避免非预期重置。
- 局部操作优先产生局部更新，不以整页刷新打断当前工作上下文。
- 跨层级操作应明确当前作用对象和影响范围，避免用户把页面级、区域级和单条对象操作混为一谈。

## 8. 降低认知负担

- 优先让用户识别，而不是要求用户记忆；让可选项、当前值和前置条件在需要时可见。
- 控制同一时刻需要理解和选择的内容数量，避免一次呈现所有能力。
- 为高频和常规情况提供合理默认值与短路径，把低频复杂性留在需要时出现。
- 信息密度和操作步数不是越少越好；简化不能以隐藏关键差异、制造歧义或失去控制为代价。

## 9. 保证操作可感知

- 可操作元素应具备稳定、明确的交互暗示，并在悬停、聚焦、选中、禁用和执行中保持可区分。
- 不只依赖颜色传达状态或结果，同时使用文字、形状、位置或图标等冗余线索。
- 点击区域、文字可读性、对比度和键盘焦点应支持不同操作方式和感知能力。
- 图标、缩写和新概念只有在含义足够明确时才能独立使用。

## 10. 保持克制

- 每个元素都应承担信息、操作、反馈或关系表达中的至少一种职责。
- 不用额外卡片、图表、弹窗、步骤或动效掩盖结构问题，也不以视觉丰富代替交互价值。
- 不为了展示能力增加入口，不为了追求新颖破坏一致性，不为了减少页面内容隐藏必要信息。
- 当两个方案都能解决问题时，选择更容易理解、更可预测、更容易恢复的方案。

## 11. 保证视觉清晰与舒适

- 前景内容与背景保持足够的颜色辨识度，正文、辅助文字、图标、边界和焦点状态在各自背景上都应清晰可读；不要用过于接近的颜色勉强区分信息。
- 优先使用系统主题与已有 Design Token，以中性色建立基础层级，只在品牌操作和明确的业务状态中使用强调色，不自行扩充色板或堆叠相近颜色。
- 通过留白、对齐、字号和字重建立稳定层级，控制单屏信息密度；避免依赖厚重边框、强阴影、渐变或过多卡片制造结构。
- 简洁不等于把所有元素弱化成相同样式。保留清楚的分组、主次和关键操作强调，同时减少无业务作用的装饰，让界面安静、舒适且易于持续阅读。

## 12. 符合 Web 平台特性

- 遵循桌面 Web 常用交互习惯，正确处理悬停、聚焦、键盘操作、滚动、浮层和内容溢出。
- 页面应随可用宽度自适应：宽屏合理利用空间，窄屏通过换行、收缩、重排或局部滚动保持内容和操作可用。
- 只需适配桌面端的宽屏与窄屏，不考虑移动端。

## 原则冲突时

按以下顺序取舍：业务含义正确、用户可控且可恢复、界面清晰可理解、行为一致可预测、操作高效，最后才是表现上的新颖与丰富。
